Double covers (experimental)

This page describes experimental and provisional functionality. The frontend DeRham.DoubleCover and its methods are not exported or declared public.

Given a smooth double cover of projective space branched along a homogeneous polynomial $F$ of even degree over a finite field of odd characteristic, DeRham.zeta_coefficients computes the L-polynomial of the primitive, anti-invariant middle cohomology. Its weight is the dimension $n$ of the base projective space. The supported input has even branch degree, odd characteristic, and a smooth branch polynomial over $\mathbb{F}_p$.

The double-cover computation requires explicit series_precision and algorithm_precision values. relative_precision is optional and defaults to the existing Weil-bound formula. These precision choices are not certified: there is no precision proof for this frontend yet. Only the depth-first CPU algorithm is supported.

Each precision may be given as a scalar for all pieces or, where supported, as a vector. relative_precision vectors have one entry per Hodge polygon piece in the order used by calculate_relative_precision. series_precision vectors have one entry per pole order in ascending order. algorithm_precision is a single integer.

The only supported entry points for this frontend are DeRham.zeta_coefficients and DeRham.get_basis_of_cohomology. Other invariants are not implemented for double covers.

A hyperelliptic example

The quartic branch polynomial below defines a smooth genus-one double cover over $\mathbb{F}_3$. The coefficient vector is in descending order.

julia> using DeRham, Oscar

julia> R, (x, z) = Oscar.polynomial_ring(Oscar.GF(3), [:x, :z]);

julia> F = x^4 + z^4;

julia> DeRham.zeta_coefficients(
           DeRham.DoubleCover(F);
           algorithm = :depthfirst,
           series_precision = 2,
           algorithm_precision = 5,
       )
3-element Vector{ZZRingElem}:
 3
 0
 1

DeRham.zeta_coefficients — Method
zeta_coefficients(fe::ZetaFrontend; ...)

Computes the zeta coefficients for a supported $ZetaFrontend$ over a finite field. Supported frontends are $ProjectiveHypersurface$ and $DoubleCover$. The returned vector contains the coefficients of the middle-cohomology L-polynomial in descending powers of $T$, as ZZRingElems, with constant coefficient 1 last. If the frontend is not smooth, this method returns false.

Keyword arguments:

  • S=[-1]: controls the S-smooth model used by the reduction; the default sentinel expands to all indices 0:n, where n is the dimension of the ambient projective space.
  • verbose=0: controls diagnostic output; zero prints nothing and larger values print progressively more detail.
  • changef=true: if the input is not an S-smooth model, allows the algorithm to try a random change of variables to find one. With false, or if no suitable model is found, the method returns false.
  • givefrobmat=false: if true, returns (F, coeffs), the Frobenius matrix and the coefficient vector, instead of just the coefficient vector.
  • algorithm=:default: selects the controlled-reduction algorithm; :default chooses automatically.
  • relative_precision, series_precision, and algorithm_precision: explicit, uncertified precision inputs for non-hypersurface frontends. Hypersurface frontends reject these keywords. $DoubleCover$ requires series_precision and algorithm_precision; relative_precision is optional and defaults to the existing Weil-bound formula. relative_precision accepts an integer for all Hodge pieces or a vector in the order returned by calculate_relative_precision; its length must match the Hodge polygon. series_precision accepts an integer for all pole orders or a vector in ascending pole-order order. algorithm_precision is an integer. Boolean values are not accepted for any explicit precision keyword.
  • use_gpu=false: enables GPU execution for supported operations.
  • use_threads=false: enables threaded execution for supported operations.

The termorder, vars_reversed, fastevaluation, always_use_bigints, context, and precision_info keywords are internal or experimental and may change. Their current defaults are :invlex, false, true, false, nothing, and nothing, respectively.

The returned coefficients can be passed to L_polynomial, zeta_function, and other coefficient-taking invariants.

Examples

julia> f = DeRham.fermat_hypersurface(3, 3, 7);

julia> fe = DeRham.ProjectiveHypersurface(f);

julia> DeRham.zeta_coefficients(fe)
3-element Vector{ZZRingElem}:
 7
 1
 1
